# Подключение Модуля управления к Pixhawk 6C и настройка

**Автопилот:** Holybro Pixhawk 6C (FMUv6C), прошивка ArduRover
**Модуль:** встроенный пульт на ESP32, сборка `release`
**Аудитория:** сотрудник, выполняющий монтаж и настройку стенда

Документ описывает подключение и настройку. Порядок функциональных проверок после настройки — в разделе 8.

---

## 1. Что понадобится

**Оборудование:**
- Pixhawk 6C с установленной ArduRover (проверялось на V4.6.3)
- Модуль управления (ESP32) с прошитой сборкой `release`
- Кабель JST-GH 6-pin для разъёма TELEM2 (входит в комплект Pixhawk 6C)
- microSD-карта для Pixhawk (обычно уже установлена)
- GPS-модуль, подключённый к Pixhawk (**обязателен**, см. п. 4.2)
- ПК с Mission Planner

**Файлы:**
- `mission_select.lua` — из корня проекта
- Файлы маршрутов и манифест (готовятся по п. 5)
- `.pio/build/release/` — образы боевой сборки Модуля

---

## 2. Разъём TELEM2 на Pixhawk 6C

Разъёмы на Pixhawk 6C подписаны на корпусе. Нужен **TELEM2** — JST-GH, 6 контактов.

Распиновка соответствует стандарту разъёмов Pixhawk (нумерация от края платы, контакт 1 обычно помечен точкой/треугольником на разъёме или красным проводом в штатном кабеле):

| Контакт | Сигнал | Уровень | Используем? |
|---|---|---|---|
| 1 | VCC (+5 В) | 5 В | **НЕТ** — не подключать |
| 2 | TX (выход Pixhawk) | 3.3 В | Да |
| 3 | RX (вход Pixhawk) | 3.3 В | Да |
| 4 | CTS | 3.3 В | Нет |
| 5 | RTS | 3.3 В | Нет |
| 6 | GND | — | Да |

Логические уровни последовательных портов Pixhawk — 3.3 В, что совпадает с ESP32. Преобразователи уровня не нужны и не предусмотрены (NFR-13 требований).

---

## 3. Схема подключения

Линии данных подключаются **перекрёстно**: передатчик одного устройства к приёмнику другого.

| Pixhawk 6C TELEM2 | | Модуль (ESP32) |
|---|---|---|
| Контакт 2 — TX | → | **GPIO25** (RX) |
| Контакт 3 — RX | ← | **GPIO14** (TX) |
| Контакт 6 — GND | ↔ | **GND** |
| Контакт 1 — +5 В | ✗ | не подключается |

### Обязательно к соблюдению

- **Контакт 1 (+5 В) оставить неподключённым.** Модуль питается от собственного преобразователя (NFR-14). Подача 5 В на 3.3-вольтовые входы ESP32 выведет их из строя.
- **Общий GND обязателен.** Без него связи не будет, даже если TX/RX подключены верно — это самая частая причина «модуль не видит автопилот».
- **Перепутанные TX/RX — вторая по частоте причина.** Признак: связь не поднимается, но ничего не греется и не сбоит. Если сомневаетесь в нумерации контактов на кабеле — прозвоните GND тестером относительно корпуса разъёма и отсчитывайте от него.

## 4. Параметры ArduPilot

Задаются в Mission Planner: **CONFIG → Full Parameter List**, поиск по имени, затем **Write Params**.

### 4.1. Обязательные параметры

| Параметр | Значение | Назначение |
|---|---|---|
| `SERIAL2_PROTOCOL` | 2 | MAVLink2 на TELEM2 |
| `SERIAL2_BAUD` | 115 | 115200 бод (в ArduPilot задаётся в тысячах) |
| `BRD_SER2_RTSCTS` | 0 | Аппаратное управление потоком отключено — линии CTS/RTS не разведены |
| `MAV_GCS_SYSID` | **200** | sysid Модуля. Обязан совпадать, иначе автопилот не примет `MANUAL_CONTROL` от Модуля (FR-4) |
| `SCR_ENABLE` | 1 | Включает Lua-скриптинг. **Требует перезагрузки автопилота** |
| `MIS_RESTART` | 1 | Миссия стартует сначала |
| `MIS_DONE_BEHAVE` | 0 | По завершении маршрута — Hold |
| `BRD_SAFETY_DEFLT` | 0 | Safety switch отключён |
| `RC_OVERRIDE_TIME` | 0.3…0.5 | Таймаут возврата управления радиоканалу |

После изменения `SCR_ENABLE` и `SERIAL2_*` — **перезагрузить автопилот**, иначе изменения не вступят в силу. После перезагрузки параметры `SCR_USER1` и `SCR_USER2` появятся в списке (через них работает обмен с Модулем).

### 4.2. GPS обязателен

Lua-скрипт перед загрузкой маршрута проверяет расстояние от текущей позиции до первой точки. Без валидной позиции (GPS/EKF) загрузка **всегда** будет отклоняться с `MLOAD ERR ... nopos`.

На закрытом помещении фикса не будет. Для проверки загрузки маршрутов нужна открытая площадка либо GPS-повторитель.

### 4.3. Проверка объёма памяти скриптов

Если после установки скрипта в Messages появляются ошибки нехватки памяти — увеличить `SCR_HEAP_SIZE` (например, до 100000) и перезагрузить автопилот.

## 5. Подготовка SD-карты

Извлечь microSD из Pixhawk, разместить файлы:

```
APM/scripts/mission_select.lua     ← скрипт из корня проекта
APM/missions.txt                   ← манифест маршрутов
APM/mission1.txt                   ← маршрут №1
APM/mission2.txt                   ← маршрут №2
...
```

Каталог `APM/scripts/` может отсутствовать — создать вручную.

### 5.1. Формат манифеста `missions.txt`

Построчно: номер, символ табуляции, название.

```
1	Sklad_A - Angar_B
2	Angar_B - Sklad_A
3	Sklad - Pogruzka
```

Требования к содержимому:
- Номер обязан соответствовать имени файла: строка `2` → файл `mission2.txt`.
- Максимальный номер — **10** (ограничение `MAX_MISSION` в скрипте).
- **Названия латиницей.** Строка ответа ограничена ~50 символами вместе с префиксом `MLIST <номер> `, а кириллица в UTF-8 занимает по 2 байта на символ — длинное русское название не поместится и список придёт обрезанным.

### 5.2. Формат файлов маршрутов

Стандартный **QGC WPL 110** — тот, в котором Mission Planner сохраняет миссию (File → Save WP File). Первая строка файла — заголовок `QGC WPL 110`, далее точки, начиная с нулевой (home).

### 5.3. Ограничение по расстоянию — учесть при подготовке маршрутов

Скрипт отклоняет загрузку, если первая путевая точка дальше **50 метров** от текущего положения платформы (`MAX_DIST_TO_WP1`).

Практически это означает: тестовые маршруты нужно строить вокруг того места, где физически находится платформа во время проверки. Маршрут, нарисованный в другой части карты, всегда будет отклоняться с `MLOAD ERR ... too_far`.

## 6. Прошивка Модуля боевой сборкой

Процедура прошивки и адреса — как в `flashing_and_verification.md`, раздел 3. Отличие только в каталоге:

```
.pio\build\release\bootloader.bin    @ 0x1000
.pio\build\release\partitions.bin    @ 0x8000
.pio\build\release\firmware.bin      @ 0x10000
```

### Как убедиться, что залита правильная сборка

На экране Модуля **не должно быть оранжевого баннера «РЕЖИМ ОТЛАДКИ — ДАННЫЕ СИНТЕТИЧЕСКИЕ»**.

Если баннер есть — залита отладочная сборка, она работает на выдуманных данных и к Pixhawk не обращается вообще. Проверки в таком виде бессмысленны.

## 7. Проверка связи

Подать питание на оба устройства.

### 7.1. Со стороны Модуля

Ключ в OFF. В строке статуса на экране:
- **нет** пометки `[СВЯЗЬ ПОТЕРЯНА]`;
- режим (`HOLD`/`MANUAL`/`AUTO`) и состояние арминга показывают реальные значения, а не `?`.

### 7.2. Со стороны Pixhawk

В Mission Planner на вкладке **Messages** после перезагрузки автопилота должна появиться строка:

```
mission_select.lua v3 loaded
```

Её отсутствие означает, что скрипт не запустился: проверить `SCR_ENABLE=1`, наличие файла в `APM/scripts/` и перезагрузку автопилота.

---

## 8. Функциональные проверки

Выполнять в указанном порядке — каждая следующая опирается на предыдущую.

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Ключ в OFF | На экране список маршрутов из манифеста. В Messages проходят строки `MLIST 1 ...`, `MLIST END N` |
| 2 | Вращение энкодера | Курсор перемещается по списку |
| 3 | Короткое нажатие энкодера | Открывается карточка маршрута |
| 4 | Удержание энкодера ~2 с | Экран результата: число точек, дистанция до WP1, длина. Значения приходят от Pixhawk |
| 5 | Ключ в LOCAL | Платформа армится, режим меняется на MANUAL. Смена режима видна в Mission Planner |
| 6 | Ключ в OFF | HOLD → остановка → дизарм. Дизарм подтверждается в Mission Planner |
| 7 | Ключ в AUTO (после успешного п. 4) | Экран «Готов к пуску» |
| 8 | Кнопка «Пуск» | Арминг → переход в AUTO → **платформа начинает движение** |

**Пункт 8 запускает реальное движение платформы.** Выполнять только на свободной площадке либо с колёсами, вывешенными над поверхностью.

### 8.1. Отдельно проверить (открытые вопросы требований)

- **№1 — смена режима при неподвижном переключателе пульта.** При выполнении п. 5 переключатель режимов на пульте диспетчерской не трогать. Убедиться, что команда Модуля всё равно переводит режим.
- **№2 — приоритет RC над Модулем.** При активном локальном управлении тронуть стики пульта диспетчерской — управление должно перехватываться пультом.
- **№5 — выдача списка маршрутов.** Пункт 1 таблицы выше и есть эта проверка. Функция `SCR_USER2` **ни разу не проверялась на реальном железе** — только на синтетических данных. Это наиболее вероятное место отказа при первом запуске.

## 9. Диагностика типовых проблем

| Симптом | Вероятная причина |
|---|---|
| `[СВЯЗЬ ПОТЕРЯНА]`, режим `?` | Нет общего GND; перепутаны TX/RX; неверный `SERIAL2_PROTOCOL`/`SERIAL2_BAUD`; не та сборка Модуля |
| Связь есть, но список маршрутов не приходит | Скрипт не загружен (`SCR_ENABLE`, перезагрузка); нет `APM/missions.txt`; смотреть Messages на `MLIST ERR nofile` / `MLIST ERR parse` |
| `MLOAD ERR ... nopos` | Нет GPS-фикса — проверка расстояния невозможна (п. 4.2) |
| `MLOAD ERR ... too_far` | Первая точка маршрута дальше 50 м от платформы (п. 5.3) |
| `MLOAD ERR ... armed` | Платформа заармлена — загрузка запрещена. Перевести ключ в OFF |
| `MLOAD ERR ... nofile` | Нет файла `missionN.txt` для номера из манифеста |
| Список приходит обрезанным | Слишком длинные названия в манифесте (п. 5.1) |
| Арминг отклонён | Pre-arm проверки автопилота. Причина отображается на экране Модуля и в Messages |

Полный перечень кодов `MLOAD ERR` — в Приложении А.1 документа требований.

### Что фиксировать при обращении к разработчику

- вывод serial-монитора Модуля (115200 бод);
- вкладка Messages в Mission Planner за тот же период;
- значения параметров Pixhawk из раздела 4 на момент проверки.

---

## 10. Не входит в этот этап

- **Джойстик** — не закуплен, локальное движение по джойстику (FR-11…FR-19) не проверяется. Тип для серийного образца выбирается; при переходе на аналоговый потребуется перевод драйвера с I2C на АЦП.
- **Открытые вопросы №3 (дизарм в движении) и №4 (поведение при зависании прошивки)** — требуют движущейся платформы на площадке.
