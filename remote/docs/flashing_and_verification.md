# Прошивка Модуля и проверка работоспособности (синтетический режим)

**Компонент:** встроенный модуль управления платформой (ESP32)
**Сборка:** `debug_synthetic` — без подключения к Pixhawk, источник телеметрии синтетический (см. NFR-15..18 требований)
**Аудитория:** сотрудник, выполняющий прошивку и первичную проверку на стенде

---

## 1. Что потребуется

**Оборудование:**
- плата ESP32 (DevKit, классический ESP32, не S2/S3/C3)
- дисплей ST7789 (SPI)
- энкодер с кнопкой (KY-040 или аналог)
- 2 кнопки («Назад», «Пуск»)
- трёхпозиционный ключевой переключатель (OFF/LOCAL/AUTO)
- аналоговый джойстик (2 оси на потенциометрах), питание **3.3 В** (не 5 В — см. открытый вопрос №8 требований)
- кнопка «мёртвая рука» (отдельная кнопка, не часть джойстика)
- активный зуммер (со встроенным генератором тона, управляется подачей HIGH/LOW — например, модуль типа HW-508)
- USB-кабель для подключения платы к ПК

**ПО:**
- [Flash Download Tool](https://www.espressif.com/en/support/download/other-tools) от Espressif (portable, установка не требуется)
- Любой serial-терминал на 115200 бод (PuTTY, Termite и т.п.)
- Драйвер USB-UART моста платы (обычно CP210x или CH340 — если Windows не видит COM-порт после подключения платы, установить драйвер под конкретный чип моста)

**Файлы прошивки** (уже собраны, находятся в):
```
.pio\build\debug_synthetic\bootloader.bin
.pio\build\debug_synthetic\partitions.bin
.pio\build\debug_synthetic\firmware.bin
```

## 2. Распиновка (для проверки/монтажа периферии)

| Интерфейс | Периферия | GPIO |
|---|---|---|
| UART | TELEM2 (не используется в синтетическом режиме) | TX 14, RX 25 |
| ADC | Джойстик, ось X | 36 (подпись на плате `VP`, input-only) |
| ADC | Джойстик, ось Y | 39 (подпись на плате `VN`, input-only) |
| GPIO | Кнопка «мёртвая рука» | 13 (внутренняя подтяжка вверх, замыкание на GND = удержана) |
| SPI | Дисплей ST7789 | SCK 18, MOSI 23, RES 16, DC 17, CS 5 |
| GPIO | Энкодер: вращение | CLK 32, DT 33 |
| GPIO | Энкодер: кнопка «OK» | SW 27 |
| GPIO | Кнопка «Назад» | 19 |
| GPIO | Кнопка «Пуск» | 4 |
| GPIO | Ключ, контакт LOCAL | 34 (input-only, **нужен внешний pull-down резистор** — на этом пине нет внутренней подтяжки) |
| GPIO | Ключ, контакт AUTO | 35 (input-only, **нужен внешний pull-down резистор**) |
| GPIO | Зуммер подтверждения пуска AUTO (сигнал+) | 26 (выход, активный зуммер: HIGH — пищит) |

Кнопки и кнопка энкодера используют внутреннюю подтяжку ESP32 — внешние резисторы для них не нужны, схема «кнопка на GND».

Подсветка дисплея предполагается запитанной постоянно (отдельного управляющего GPIO нет).

## 3. Прошивка через Flash Download Tool

1. Подключить плату к ПК по USB.
2. Открыть Диспетчер устройств → «Порты (COM и LPT)» — записать номер появившегося COM-порта. Если порт не появился, установить драйвер USB-UART моста платы.
3. Запустить `flash_download_tool.exe`.
4. В стартовом окне выбрать:
   - **ChipType:** ESP32
   - **WorkMode:** Develop
   - нажать **OK**
5. В таблице из трёх строк указать файлы и адреса:

   | Файл | Адрес |
   |---|---|
   | `bootloader.bin` | `0x1000` |
   | `partitions.bin` | `0x8000` |
   | `firmware.bin` | `0x10000` |

   Для каждой строки: кнопка «...» → выбрать файл → вписать адрес → поставить галочку слева от строки.

6. Выставить параметры:
   - **SPI SPEED:** 40MHz
   - **SPI MODE:** DIO
   - **FLASH SIZE:** 2MB
7. Выбрать **COM**-порт (пункт 2) и **BAUD** — 921600 (при сбоях снизить до 115200).
8. Нажать **START**.
9. Если прошивка не начинается автоматически — на плате зажать кнопку **BOOT**, нажать и отпустить **EN/RESET**, отпустить **BOOT**, повторить START.
10. Дождаться зелёной полосы **FINISH** — прошивка завершена.

## 4. Проверка 1 — монитор порта (без периферии)

Выполняется сразу после прошивки, даже если дисплей/джойстик/ключ ещё не подключены.

1. Открыть serial-терминал на том же COM-порту, 115200 бод, 8N1.
2. Нажать **EN/RESET** на плате для перезапуска.
3. В первые 1-2 секунды в логе должны появиться строки:

```
esp_display module starting (synthetic_mode=1)
...
=== РЕЖИМ ОТЛАДКИ — ДАННЫЕ СИНТЕТИЧЕСКИЕ (NFR-15..18) ===
RT task on core 0, UI task on core 1 started
```

**Результат теста:**
- **Пройден**, если строки появились и лог не содержит `Guru Meditation Error`, `rst:0x... (RTC_SW...)` с повторяющимися перезапусками.
- **Не пройден**, если плата уходит в циклическую перезагрузку или лог замирает без вывода дольше нескольких секунд. В этом случае скопировать полный вывод терминала (в том числе строки с адресами вида `PC: 0x...`) для дальнейшего разбора.

---

## 5. Проверка 2 — дисплей

Требуется подключённый дисплей (п. 2).

1. Подать питание / перезапустить плату.
2. Убедиться, что вверху экрана постоянно отображается оранжевая полоса:
   ```
   РЕЖИМ ОТЛАДКИ - ДАННЫЕ СИНТЕТИЧЕСКИЕ
   ```
   Эта полоса не должна пропадать ни при каких действиях — это признак того, что прошивка собрана в отладочном, а не боевом режиме.
3. Ниже неё — строка статуса (положение ключа, режим, состояние арминга).
4. Установить ключ в положение **OFF**. В течение 1-2 секунд экран должен показать список из трёх маршрутов:
   ```
   1 Sklad_A - Angar_B
   2 Angar_B - Sklad_A
   3 Sklad - Pogruzka
   ```

**Результат теста:** пройден, если баннер отладки виден постоянно и список маршрутов появляется при ключе в OFF.

---

## 6. Проверка 3 — ключ (три положения)

Требуется подключённый ключ и дисплей.

| Действие | Ожидаемый экран |
|---|---|
| Ключ → **OFF** | список маршрутов (после краткого «Запрос...») |
| Ключ → **LOCAL** | «Локальное управление», режим MANUAL, состояние ARM |
| Ключ → **AUTO** (без загрузки маршрута) | «Пуск недоступен: маршрут не загружен» |

Дополнительно (если есть техническая возможность одновременно замкнуть оба контакта ключа): красный баннер «ОШИБКА: недопустимое положение ключа».

**Результат теста:** пройден, если для каждого положения ключа отображается соответствующий экран без задержки более 2 секунд.

---

## 7. Проверка 4 — энкодер и кнопки (полный сценарий выбора и загрузки маршрута)

Требуется подключённые ключ, энкодер, кнопки, дисплей.

1. Ключ → **OFF**, дождаться списка маршрутов.
2. Повернуть энкодер — курсор `>` должен перемещаться между тремя строками списка.
3. Коротко нажать энкодер (без задержки, обычный клик) — должна открыться карточка «Маршрут №N» (N — номер выбранной строки).
4. Нажать и удерживать энкодер около 2 секунд — на экране должен отображаться растущий процент загрузки, а по завершении удержания — автоматический переход на экран результата:
   ```
   Маршрут №1 загружен
   Точек: 10
   До WP1: 4 м
   Длина: 240 м
   ```
   (числа зависят от выбранного маршрута — см. таблицу ниже)
5. Из карточки маршрута (шаг 3, не входя в загрузку) нажать кнопку «Назад» — должен произойти возврат в список без перехода к загрузке.
6. Ключ → **AUTO** — должен появиться экран «Готов к пуску — нажмите «Пуск»» (маршрут был загружен на шаге 4, в этом же цикле OFF).
7. Нажать и удерживать кнопку «Пуск» — см. Проверку 6 (раздел ниже) для подробного сценария подтверждения. После завершения подтверждения экран должен последовательно показать: «Арминг...» → «Перевод в AUTO...» → «Движение по маршруту».

**Ожидаемые числа результата загрузки по маршрутам:**

| Маршрут | Точек | До WP1, м | Длина, м |
|---|---|---|---|
| 1 — Sklad_A - Angar_B | 10 | 4 | 240 |
| 2 — Angar_B - Sklad_A | 10 | 6 | 240 |
| 3 — Sklad - Pogruzka | 6 | 12 | 380 |

**Результат теста:** пройден, если все переходы экранов происходят как описано и числа результата загрузки совпадают с таблицей для выбранного маршрута.

## 8. Проверка 5 — джойстик (только в положении LOCAL)

Требуется подключённые ключ, джойстик (оси на GPIO36/39, питание 3.3 В), кнопка «мёртвая рука» (GPIO13), дисплей.

1. Ключ → **LOCAL**.
2. Если джойстик не в центральном положении — экран должен показывать «Верните джойстик в нейтраль» и не более того (без «Готов»/«Движение разрешено»).
3. Отпустить джойстик в центр — экран должен смениться на «Готов, ждём мёртвую руку».
4. Зажать кнопку «мёртвая рука» и отклонить стик — экран должен показать «Движение разрешено».
5. Отпустить кнопку «мёртвая рука» — экран должен немедленно (без плавного затухания) вернуться к «ждём мёртвую руку».
6. **Проверка полярности (открытый вопрос №9):** при удерживаемой «мёртвой руке» отсоединить её разъём — экран обязан вернуться к «ждём мёртвую руку», а не остаться в «Движение разрешено». Если поведение обратное — инвертировать `MODULE_DEAD_MAN_ACTIVE_LOW` в `config.h` и пересобрать.
7. **Калибровка (Приложение Б требований):** если в центре хода экран не показывает нейтраль или ход по осям несимметричен — снять сырые значения и подставить `MODULE_JOYSTICK_ADC_CENTER_X/Y`, `MODULE_JOYSTICK_RAW_FULL_SCALE`, при обратном направлении осей — `MODULE_JOYSTICK_X_INVERT`/`_Y_INVERT`.

**Результат теста:** пройден, если поведение экрана соответствует каждому из шагов 2-5.

## 9. Проверка 6 — подтверждение пуска AUTO (FR-40.5..40.7)

Требуется подключённые ключ, зуммер, дисплей; маршрут загружен, ключ в **AUTO**, экран «Готов к пуску — нажмите «Пуск»».

1. Нажать и удерживать кнопку «Пуск». Сразу должна появиться полоса под текстом «Удерживайте «Пуск»...», заполняющаяся слева направо за ~3 секунды; одновременно зуммер должен пищать примерно раз в секунду (1 Гц).
2. **Отпустить кнопку до заполнения полосы** (например, через ~1 секунду) — экран должен немедленно вернуться к «Готов к пуску — нажмите «Пуск»», зуммер должен замолчать, полоса — исчезнуть. Повторное удержание должно начинать отсчёт заново с нуля.
3. Нажать и удерживать кнопку «Пуск» непрерывно ~3 секунды до полного заполнения полосы. По заполнении экран должен смениться на «Активация Авторежима через 5» с обратным отсчётом по одной секунде (5→4→3→2→1), зуммер должен пищать чаще, примерно раз в полсекунды (2 Гц).
4. **Отпустить кнопку во время отсчёта** — отсчёт должен продолжаться как ни в чём не бывало (эта фаза необратима кнопкой).
5. Дождаться конца отсчёта — экран должен перейти на «Арминг...» → «Перевод в AUTO...» → «Движение по маршруту», зуммер должен замолчать.
6. Отдельно проверить: во время отсчёта (шаг 3) перевести ключ из AUTO в любое другое положение — отсчёт должен прерваться немедленно (экран уходит со страницы AUTO), зуммер — замолчать.

**Результат теста:** пройден, если поведение полосы/отсчёта/зуммера соответствует каждому из шагов 1-6.

---

## 10. Действия при обнаружении отклонений

Для каждого несовпадения с ожидаемым результатом зафиксировать:
- номер раздела проверки;
- что ожидалось / что получено;
- полный вывод serial-монитора на момент проблемы (если плата в цикле перезагрузок — обязательно, включая строки с адресами `PC:`/`EXCVADDR:`);
- фотографию/описание текущей схемы подключения периферии, если проблема касается конкретного устройства (дисплей/джойстик/ключ/энкодер).

Собранную информацию передать разработчику прошивки для разбора — часть проверок (сценарии отказа арминга, «маршрут слишком далеко») в этой сборке не запускаются без дополнительной доработки и в рамках данного документа не проверяются.
