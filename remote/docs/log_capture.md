# Снятие лога Модуля при отказе загрузки

**Задача:** зафиксировать вывод ESP32 в момент старта, когда Модуль не запускается при подключённом Pixhawk.
**Условия:** ESP32 питается по USB, порт COM12, терминал PuTTY.

---

## 1. Почему просто «открыть терминал» недостаточно

Весь стартовый вывод ESP32 проходит за первые ~0.5 секунды. Если открыть терминал после подачи питания, эти строки уже потеряны — а именно в них причина отказа.

При питании по USB подача питания и появление COM-порта — одно и то же событие, поэтому открыть терминал заранее невозможно. Обходим это кнопкой **EN/RESET** на плате: она перезапускает ESP32, не разрывая USB, и COM-порт остаётся на месте.

Важно: преобразователь USB-UART на плате питается от USB и определяется системой **независимо** от того, загрузился ESP32 или завис. То есть COM12 будет доступен в любом случае.

---

## 2. Настройка записи в файл (PuTTY)

Выполняется один раз.

1. Запустить PuTTY, **не подключаясь**.
2. В дереве слева: **Session → Logging**.
3. «Session logging» → выбрать **All session output**.
4. «Log file name» → указать путь, например `C:\putty_log.txt`.
5. Отметить **Always append to the end of it** — тогда все попытки соберутся в один файл и не затрут друг друга.
6. Вернуться в **Session**: тип **Serial**, строка `COM12`, скорость `115200`.
7. **Open**.

Терминал открыт, запись идёт.

---

## 3. Тест 1 — эталон (линия от Pixhawk отключена)

Нужен для сравнения: так выглядит нормальный старт.

1. Отсоединить провод **Pixhawk TX → GPIO25**.
2. Терминал открыт (раздел 2).
3. Нажать на плате **EN/RESET**.

Ожидается: обычный лог загрузки, заканчивающийся строками про инициализацию дисплея и запуск задач, и на экране появляется интерфейс.

---

## 4. Тест 2 — перезапуск при активной линии

Главный тест. Здесь ESP32 стартует, когда Pixhawk уже передаёт данные, но питание с платы не снималось.

1. Pixhawk включён и работает.
2. **Подключить** провод Pixhawk TX → GPIO25.
3. Терминал открыт, запись идёт.
4. Нажать **EN/RESET**.
5. Дождаться 10–15 секунд и посмотреть, что появилось в терминале.

---

## 5. Тест 3 — холодный старт

Проверяет сценарий из багрепорта: подача питания при уже активной линии.

1. Pixhawk включён, провод Pixhawk TX подключён.
2. Вынуть USB из ESP32, подождать 5 секунд.
3. Вставить USB обратно.
4. Посмотреть **на экран Модуля** (лог здесь снять не получится — COM-порт исчезает вместе с питанием).

Фиксируется только факт: интерфейс появился или экран остался чёрным.

---

## 6. Что смотреть в логе

### Признаки, которые нужно найти

| Что видно в логе | Что это значит |
|---|---|
| `Guru Meditation Error` и следом `Backtrace:` | Программная ошибка. **Скопировать весь блок целиком**, включая строки после Backtrace |
| Строка `rst:0x...` повторяется раз за разом | Циклическая перезагрузка. Важна причина в скобках: `RTC_SW_CPU_RESET`, `TG0WDT_SYS_RESET`, `SW_CPU_RESET` |
| `Brownout detector was triggered` | Просадка питания |
| Лог обрывается на середине и дальше тишина | Зависание. Важно, **на какой именно строке** остановился вывод |
| Вывода нет вообще, пустой экран терминала | Чип не стартует физически |

### Нормальный старт для сравнения

При исправной загрузке лог доходит до строк вида:

```
I (...) display: ST7789 panel initialized (320x170, phys 170x320)
I (...) mavlink_bridge: MAVLink bridge started (sysid=200, target sysid=1)
I (...) module_main: RT task on core 0, UI task on core 1 started
I (...) lvgl_port: LVGL initialized (320x170, buffer 40 rows)
```

Если вывод обрывается раньше — запомнить последнюю строку, она указывает на этап, где всё встало.

### Диагностика связи

Дальше раз в 5 секунд должна идти строка:

```
mavlink_bridge: UART RX: bytes=... msgs=... parse_err=... first_byte=...
```

- `bytes=0` — от Pixhawk ничего не приходит;
- `bytes>0, msgs=0` — данные идут, но не разбираются (скорее всего скорость);
- `msgs` растёт — связь работает.

---

## 7. Сводная таблица результатов

Заполнить по итогам тестов 1–3:

| Тест | Линия Pixhawk | Способ запуска | Результат |
|---|---|---|---|
| 1 | отключена | EN/RESET | |
| 2 | подключена | EN/RESET | |
| 3 | подключена | холодный старт (USB) | |

### Как читать

- **Тест 2 прошёл, тест 3 нет** → данные на линии не мешают, проблема именно в подаче питания при активной линии. Подтверждает версию с паразитным питанием через вход; лечится токоограничивающим резистором, программно не решается.
- **Тест 2 тоже не прошёл** → причина программная, и она будет видна в логе теста 2.
- **Тест 1 не прошёл** → отказ не связан с Pixhawk вообще, разбираться отдельно.

---

## 8. Что передать разработчику

1. Файл `C:\putty_log.txt` целиком (в нём будут все попытки подряд).
2. Заполненную таблицу из раздела 7.
3. Если был `Guru Meditation Error` — отдельно скопировать этот блок с трассировкой.

---

## Приложение. Альтернатива без PuTTY

Тот же лог можно снимать средствами PlatformIO — с автоматической расшифровкой адресов в имена функций и номера строк, что заметно ускоряет разбор паники:

```bash
pio device monitor -e release -p COM12 | tee putty_log.txt
```

Выход из монитора — `Ctrl+C`.
